# Investigation 02 — Repeated Windows Login Failures

## Overview

**Platform:** Windows 11  
**Monitoring tool:** Wazuh  
**Detection rule:** 60204  
**Alert level:** 10  
**Agent:** WIN-PROJECTS01  
**Outcome:** Expected activity generated during a controlled lab test

## Objective

Generate repeated failed Windows login attempts and investigate how Wazuh detects a pattern of authentication failures.

## Procedure

1. Generated several incorrect login attempts on my own Windows virtual machine.
2. Reviewed the associated authentication alerts in Wazuh.
3. Investigated the aggregated alert generated by rule `60204`.
4. Reviewed subsequent authentication activity to assess whether there was evidence of an unexpected successful login.

## Findings

Wazuh generated rule `60204`, described as **"Multiple Windows logon failures"**, with an alert level of 10.

The rule's displayed configuration showed a frequency of 8, and the alert fired once during the observed test.

The failed attempts were generated intentionally as part of the lab exercise. A successful Windows authentication-related event was also observed afterwards.

## Follow-up Event Assessment

A subsequent Windows Event ID `4624` was observed with logon type `7`, which corresponds to a workstation unlock.

I confirmed that I had unlocked my own Windows session around that time. Therefore, the event was consistent with my known lab activity and was not, by itself, evidence of an attacker successfully logging in.

## Analyst Assessment

Repeated authentication failures can indicate mistyped credentials, a misconfigured service or potential password-guessing activity. The alert level alone does not establish malicious intent.

In a real SOC investigation, I would correlate the failed attempts with account details, source information, event timing and any subsequent successful authentication. I would also consider whether the activity matches the user's normal behaviour.

## Recommended Follow-up

- Examine repeated failures over an appropriate time window.
- Correlate authentication failures with successful logins or workstation unlocks.
- Review source addresses and account context where available.
- Escalate when supporting evidence indicates possible credential attacks.

## Skills Demonstrated

- Correlation of related security alerts
- Authentication-event investigation
- Review of Wazuh detection rules and severity
- Contextual assessment of follow-up events
- Evidence-based triage and documentation

## Conclusion

This investigation demonstrated Wazuh's ability to identify repeated Windows logon failures through a higher-severity detection rule. It also reinforced that analysts should correlate related events and validate context before concluding that an account has been compromised.
